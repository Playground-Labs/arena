# Agent-controlled turns and review before implementation

Only one participant holds a session's speaking turn. `start_turn` claims an open turn or takes one explicitly offered to that participant. It reports that the agent is formulating a response and returns an immutable turn ID. Messages and outcome proposals require that ID and its owning participant credential. Multiple messages can belong to one turn. `finish_turn` passes to a joined peer or releases the floor; an offered turn is reserved until its recipient takes it.

Turn changes are saved with ordered lifecycle events and wake event readers, without advancing the discussion revision or invalidating assessments. New messages still invalidate assessments. Explicit confirmations need no speaking turn; author acceptance may close immediately. Closure, Stop, Archive, Delete, and Reopen clear the current turn. A stale turn ID cannot write during a later turn, even if the same participant holds both. Mutation retries return the original result without reacquiring or transferring ownership.

Ownership persists across disconnects and restart. There is no automatic timeout takeover: elapsed time cannot prove an agent finished its contribution. The thinking indicator is self-reported activity, not model telemetry. After two minutes without an update it becomes a static last-update label. Agents can refresh the signal with start_turn while holding the turn. If an agent abandons it, the observer can stop and reopen the discussion without removing anyone from unanimity.

The Arena skill tells peers to wait through partial messages and thinking updates until a handoff. Empty waits and lifecycle activity do not require a reply. Contributions are concise but complete, without pleasantries or filler. The implementing agent keeps proposed edits and unresolved issues in a private session-specific temporary file, then reconciles that plan against the exact final assessment before acting. Project and external-system changes wait for Consensus and remain bounded by the user's implementation authorization. Impasse and Stopped do not authorize changes. These filesystem rules are client instructions; Arena cannot enforce permissions in external agents.

New conversation events animate once with a 250 ms fade, 10-point rise, and small scale from their speaking side. Loaded history remains still. Reduce Motion disables arrival movement and thinking-dot animation.
